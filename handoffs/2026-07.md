## PR #26 point-in-time and CI hardening — 2026-07-25

### Purpose

Address the remaining PR #26 review findings so historical packets cannot use later retrievals, append-only enforcement compares committed revisions, offset timestamps compare as absolute instants, registry metadata is enforced, and clean CI installs are reproducible.

### Files created, updated, or deleted

- Added `.github/workflows/validate.yml`, `package-lock.json`, `tests/market-packet.test.mjs`, and `tests/append-only.test.mjs`.
- Updated packet generation, data validation/library code, registry metadata, data tests, the generated empty packet, `package.json`, root/data READMEs, `Handoff.md`, and this monthly record.
- Deleted no production data and added no real or synthetic production observations.

### Important implementation decisions

- `--as-of` requires an ISO 8601 instant with an explicit `Z` or numeric offset; its deterministic default is the target date at `23:59:59.999Z`.
- Retrieval cutoffs, latest retrieval, and vintage choice use parsed epoch times. Economic vintage grouping uses `indicator_id`, `period`, and `released_at` and retains only the latest eligible retrieval in generated output without changing stored history.
- `DATA_BASE_REF` is the sole append-only base input. Git name-status output between its merge base and `HEAD` permits only added paths; modifications, deletions, renames, copies/replacements, and same-path replacements fail. Missing local bases warn, while missing CI bases fail.
- The correction escape hatch requires `ALLOW_DATA_CORRECTION=1` plus a non-empty `DATA_CORRECTION_REASON` and always warns.
- Registry entries now declare record types, allowed frequencies/units/change bases, and market asset classes. Data names are warning-level because source-specific labels may legitimately differ.
- `ajv` and `js-yaml` are direct development dependencies because they support repository validation/generation rather than application runtime.
- CI uses Node 20, full checkout history, `npm ci`, and `npm run validate`; PRs use the base SHA and main pushes use the prior SHA. Missing/all-zero bases fail explicitly.
